# Interactive execution

Commands run in one of three modes — `batch` (stdin closed: a reader gets EOF instead of a
hang), `scripted_input` (synthetic answers supplied up front, e.g. guesses for a game),
`interactive_pty` (a real terminal for `isatty()`, `getpass`, curses) — and a fourth runtime
state, `waiting_for_user`, when a live process asks for something only the user has.

Timeout kinds are separate concepts: startup (no output at all), idle (no progress while
running), wall clock, and user-input wait — which is not a failure. A batch command that
printed a question and stalled is classified interactive, not broken; the lesson tells the
next attempt to use scripted input or a PTY. Timed-out processes are terminated by process
group (SIGTERM, grace, SIGKILL) and their partial output is kept as evidence.

Test input (arbitrary guesses, yes/no, menu picks) is generated by the agent; only real
external input (credentials, irreversible decisions, private values) blocks autonomous
progress. A sensitive prompt is never written to the event log, and the terminal echo of a
sensitive answer is redacted from the captured output.

See `src/gcae/execution.py` and `tests/test_adaptive_execution.py` + `test_adaptive_trajectory.py`
for the exercised behavior.
